# CHECK-VAL-01 - Validation Framework Compliance

## Objectif

Verifier qu'une evaluation, une checklist ou une decision CGPA v6.1.1 applique `../VALIDATION-FRAMEWORK-v6.1.1.md`.

* Projet :
* Evaluation, checklist ou Gate :
* Phase ou jalon :
* Environnement :
* Artefact, version, commit ou digest :
* Date :
* Evaluateurs :
* CGPA Chief Delivery Officer :

## Applicabilite

* [ ] Le perimetre evalue est explicite.
* [ ] Chaque controle est applicable, non applicable avec justification, ou non execute.
* [ ] Les exemptions sont approuvees et tracees.
* [ ] Aucun manque de preuve n'est classe non applicable.

## Preuves

* [ ] Chaque preuve identifie le controle couvert.
* [ ] Les sources et chemins sont accessibles et portables.
* [ ] L'environnement et l'artefact evalues sont identifies.
* [ ] La date, le producteur et le verificateur sont traces.
* [ ] La fraicheur et les conditions d'invalidation sont verifiees.
* [ ] Aucune preuve, validation ou valeur n'est inventee.

## Resultats et bloqueurs

* [ ] Les controles utilisent PASS / PASS sous reserve / FAIL / non applicable / non execute.
* [ ] La criticite bloquante, majeure, mineure ou observation est tracee.
* [ ] Tout FAIL bloquant produit NO GO.
* [ ] Tout controle bloquant non execute produit NO GO.
* [ ] Le score et le DCL ne compensent aucun bloqueur.
* [ ] Les controles futurs d'une checklist multi-etapes sont exclus du jalon courant.

## Reserves

* [ ] Chaque reserve possede un identifiant, une criticite et un impact.
* [ ] Chaque reserve non bloquante est acceptee par une autorite identifiee.
* [ ] Un responsable, une echeance et une preuve attendue sont traces.
* [ ] Aucune reserve n'est utilisee pour neutraliser un bloqueur.
* [ ] Les reserves expirees ou levees sont historisees.

## Autorites et decision

* [ ] Les avis specialises sont distincts de la decision finale.
* [ ] La decision specialisee du Release Manager est tracee lorsque applicable.
* [ ] Le CGPA Chief Delivery Officer v6.1.1 porte la decision CGPA finale.
* [ ] La decision est GO / GO sous reserve / NO GO.
* [ ] La prochaine action autorisee est explicite.

## Historique

* [ ] Une reevaluation reference la decision precedente.
* [ ] Aucun Gate valide n'est rejoue artificiellement.
* [ ] Aucune decision, preuve, reserve ou historique utile n'est supprime.
* [ ] `/docs/project-state.md` est mis a jour apres la decision.
